# Mexion Design DNA

> 适用范围：`apps/web/src/skins/mexion/**` 以及所有 Mexion 视觉覆盖层。
>
> 唯一视觉基准：`apps/web-static-backup-20260707-2030/dist`。旧静态源码只读；Sub2API 的路由、API、Store、权限和 Feature Flag 始终是功能真源。

## 1. 核心命题

Mexion 不是“暖色 SaaS 主题”，而是一份可以操作的技术期刊：

- **纸张是空间**：页面先像纸，而不是像铺满灰底的组件画布。
- **墨色是结构**：层级主要由墨色、字重、字号、留白和细线建立。
- **朱砂是动作**：红色像印章，只落在品牌、活动项、关键动作和重要状态上。
- **版面是叙事**：编号、卷号、图版说明、基线和分栏让功能有阅读顺序。
- **动效是印刷过程**：线条被写出、墨迹渗入、印章落下；不做无语义炫技。

复刻目标不是复制旧页面的偶然缺陷，而是复现它的视觉结果、信息节奏和生成规则。后端未启用的按钮、错误的 HTML 字符串或失效交互不得被复制。

## 2. 两个场景，一套基因

### 2.1 Public / Auth：编辑出版物

首页、登录、注册、找回密码、邮箱验证和状态页使用更强的出版表达：

- 暖象牙纸底、装订边、纸纤维、低对比网格。
- 大幅 Newsreader 标题与中文 Noto Sans SC 的克制混排。
- 图版、编号、图注、角标和卷号构成“封面 / 内页”感。
- 页面可以有仪式性的分阶段入场，但必须保证内容很快可读。

### 2.2 Application：技术台账

用户端和管理端是同一本刊物的“数据附录”，密度更高，但不能退回普通 SaaS：

- 暖灰画布 + 白纸表面，结构由 1px 细线和紧凑网格承担。
- 卡片像档案页或账簿，不像悬浮玻璃块。
- 数字、时间、Token、状态和技术标签优先使用 Geist Mono。
- Newsreader 只用于页标题、关键数字和编辑性强调，不覆盖密集中文功能文字。
- 圆角、阴影和色彩都应弱于内容本身。

二者不是两套皮肤：Public 是“封面”，Application 是“内页”。色彩角色、字体角色、细线、编号和朱砂语义必须一致。

## 3. 色彩语法

### 3.1 Public 纸墨色

| 角色 | Token | 基准值 | 用途 |
|---|---|---:|---|
| 主墨 | `--mx-public-ink` | `#0F0E0C` | 标题、主结构、主按钮 |
| 次墨 | `--mx-public-lead` | `#5C564E` | 正文、说明 |
| 雾墨 | `--mx-public-mist` | `#9A938A` | 图注、卷号、元数据 |
| 朱砂 | `--mx-public-verm` | `#B5392D` | 印章、活动项、关键动作 |
| 纸张 | `--mx-public-paper` | `#F8F4EA` | 主纸面 |
| 纸张二阶 | `--mx-public-paper-2` | `#EFE8D6` | 装订、分层、纸边 |

### 3.2 Application 台账色

| 角色 | Token | 基准值 | 用途 |
|---|---|---:|---|
| 画布 | `--mx-app-bg` | `#F4F3EE` | 页面背景、侧栏 |
| 主纸面 | `--mx-app-surface` | `#FFFFFF` | 卡片、表格、浮层 |
| 主墨 | `--mx-app-ink` | `#14140F` | 标题、正文 |
| 边线 | `--mx-app-border` | `#E6E2D6` | 卡片和控件边框 |
| 朱砂 | `--mx-app-verm` | `#C8392D` | 活动项、关键 CTA |

### 3.3 使用规则

1. 朱砂在一个视口中只承担少数最高优先级信号；不能大面积铺底。
2. 绿色、琥珀、蓝色只表达成功、警告、信息、平台等业务语义，不能替代品牌朱砂。
3. 深色模式使用暖墨褐色，不使用冷蓝黑或霓虹高饱和色。
4. 封面/卷首的朱砂是“印在纸上的颜料”：深色模式仍保持 `#B5392D` 的克制密度；Auth 与 Application 的交互朱砂可提亮，以保证控件和焦点可读性。不要把所有深色朱砂机械统一成高亮红。
5. 文本层级先用墨色明度解决，最后才考虑加入新颜色。
6. 不在组件内散落新的十六进制色；新增颜色先进入 `styles/tokens.css` 并说明语义。

## 3.4 品牌标记语法

- Sidebar 默认标记不是任意的首字母图标，而是旧静态刊头使用的尖塔字形与朱砂方印；它承担“出版物刊头”的角色。
- 默认资源由 Mexion 皮肤层拥有，当前路径为 `public/assets/mexion-static-icon-master.png`；业务组件不得各自复制或重绘。
- 后端真正自定义的 `site_logo` 始终优先；空值和 Sub2API 已知默认占位路径 `/assets/icon-master.png` 才映射到皮肤刊头，避免默认资源穿透皮肤，同时不破坏站点自定义能力。
- 首页/Auth 的 8px 朱砂菱形是章节标点，不是完整 Logo；不能因为复用品牌资产而把所有装饰都替换成刊头。
- 学习设计精髓意味着保持“刊头、章节标点、动作印章”三种品牌符号的职责边界，而不是在所有位置重复同一个 Logo。
## 4. 字体角色

| 字体 | 角色 | 典型内容 |
|---|---|---|
| `Newsreader` | display / editorial | 品牌、H1/H2、关键数字、英文斜体强调 |
| `Noto Sans SC` | dense Chinese | 中文正文、表单、设置项、密集后台信息 |
| `Geist` | interface | 按钮、导航、英文正文、控件标签 |
| `Geist Mono` | metadata | 编号、时间、状态、Token、模型名、图注、卷号 |

规则：

- 标题与正文必须形成字体角色对比，不能全站只用同一种 sans。
- Mono 文本通常配合 tabular numbers、较小字号和轻微字距。
- 中文标题不为了“复古”强行全部使用衬线；应以可读性和原静态版角色为准。
- 技术值不可使用花体或斜体。

## 5. 编辑网格与节奏

- 基线单位：`6px`。常用间距优先取 `6 / 12 / 18 / 24 / 36 / 48 / 72`。
- Public 水平页边距：`clamp(28px, 6vw, 92px)`。
- 正文理想行长：`56ch`；说明文字通常不超过 `68ch`。
- 页面标题、导语、状态条、主体区之间使用留白和细线，不增加多余容器。
- 编号必须有意义：章节、步骤、图版、统计序号或时间序列；禁止纯装饰随机编号。
- 复杂设置页按“章节标题 → 简介 → 规则 → 表面/表格”组织，而不是连续堆卡片。
- 移动端保留阅读顺序和编号，不只是把桌面两栏机械压成一列。
- **空白必须有阅读意图**：留白可以承担停顿、分卷和呼吸，但不能是 Grid 等高拉伸造成的偶然死区；动态模块高度不平衡时，优先改成账簿行、连续档案叶或重新编排真实内容，绝不填入伪造数据。

## 6. 纸面、边线、圆角与阴影

### 纸面层级

1. **Canvas**：暖灰或暖墨背景，承载整体环境。
2. **Paper**：主要内容表面，接近真实纸张，不透明。
3. **Inset**：代码、筛选、次级区域，使用轻微暖色差。
4. **Float**：Dialog/Dropdown/Popover，仍是纸面，只增加足够的分离阴影。

### 边线

- 默认为 1px hairline。
- 朱砂线只用于关键段落、活动状态或印刷套色提示。
- 虚线表达裁切、草稿、可编辑或暂存语义，不能装饰性滥用。

### 圆角

- Public 图版和编辑区倾向 0–6px。
- Application 控件 6px、卡片 10px、浮层最多 14px。
- 禁止默认 `rounded-2xl/3xl` 式大圆角；圆角不能成为主要品牌特征。

### 阴影

- 普通卡片优先无阴影或仅 paper hairline。
- 只有悬浮层、抽屉和真正脱离文档流的表面使用明显阴影。
- 禁止玻璃拟态、彩色发光和大范围背景模糊。

## 7. 组件翻译规则

### Page Header

必须至少包含两种层级：章节/元数据与主标题。可选导语和一条横向规则。不能只放一个粗体 `24px` 标题。

### Card / Section

- 先判断能否用分隔线和留白完成；只有需要独立边界时才使用卡片。
- 标题区、正文区、操作区有清楚的基线和边线关系。
- Hover 只产生轻微抬升、边色变化或墨色变化。

### Table / Ledger

- 表头像索引栏：小号、Mono、字距、弱墨色。
- 数值右对齐并使用 tabular numbers。
- 行 hover 是纸张墨色变化，不用高饱和彩色块。
- 空状态仍保留台账结构，不能变成孤立大插画。

### Form / Settings

- 标签、说明、控件、错误提示按固定垂直节奏排列。
- Focus 使用墨色或朱砂边线，不能使用默认蓝色光环。
- 密码、密钥、域名、模型名使用 Mono。
- 危险操作由语义和位置建立警示，不整页涂红。

### Overlay

- Dropdown、Select、Popover、Dialog 共用暖纸表面、明确边线和统一 z-index。
- 浮层必须 portal 到不会被父级 `overflow` 裁切的位置。
- Modal 是档案夹或插页，不是透明玻璃卡。

## 8. 动效语法

只有三种主语义：

| 语义 | 曲线 | 用途 |
|---|---|---|
| `brush` | `--mx-ease-brush` | 横线、下划线、规则从左到右写出 |
| `ink` | `--mx-ease-ink` | 内容快速接触后缓慢显影、面板进入 |
| `stamp` | `--mx-ease-stamp` | 朱砂印章、关键状态、确认动作落下 |

规则：

- 先有信息顺序，再有 stagger；动画不能反过来决定 DOM 顺序。
- 常规控件反馈 140–220ms；结构变化 320–420ms；Public 仪式性入场可更长，但首屏主要内容不得长时间不可见。
- 动画优先使用 `opacity / transform / clip-path`。
- 禁止普通 bounce、持续漂浮、无语义 zoom、彩色粒子和循环发光。
- `prefers-reduced-motion: reduce` 下必须取消仪式性时序并立即显示内容。

## 9. 新页面生成规则

当旧静态版没有对应页面时，不“先不管风格”，而是按以下顺序翻译：

1. 确认页面业务主语：阅读、筛选、编辑、监控、结算或管理。
2. 选择出版原型：封面、目录、图版、账簿、档案页、勘误表、附录。
3. 用字体角色和网格建立层级，再决定是否需要卡片。
4. 从 `tokens.css` 选色，不新增随意颜色。
5. 朱砂只放在一个最关键动作或状态上。
6. 加入有语义的编号、图注、状态栏或规则线，但不能伪造业务数据。
7. 验证浅色、暖墨深色、桌面、移动端、键盘焦点和 reduced-motion。

### 9.1 页面族差异矩阵

所有现有路由与新版功能的原型选择、静态对应关系和后续状态统一记录在 [`DESIGN_EXTENSION_MATRIX.md`](./DESIGN_EXTENSION_MATRIX.md)。矩阵负责回答“这个功能为什么长成这样”，本文件负责约束“它必须使用什么设计语法”。

### 9.2 Commerce 页族生成语法

Commerce 不是一组营销卡片，而是一段可以被核对、追溯和执行的业务记录。旧静态没有完整覆盖的新页面，按真实数据形态选择以下句法：

| 业务形态 | 版式句法 | 阅读重点 | 朱砂位置 |
|---|---|---|---|
| 推荐 / 返佣 | 指标索引 → 邀请凭单 → 协议步骤 → 邀请登记册 | 关系、条件、累计值、可执行动作 | 邀请码、转余额或唯一主动作 |
| 用户订阅 | 当前状态索引 → 订阅凭单 → 权益条目 → 用量账簿 | 当前套餐、有效期、权益和消耗 | 续订、升级或状态印记 |
| 管理订阅 | 汇总索引 → 条件工具栏 → 连续订阅账簿 → 行级动作 | 用户、平台、周期、状态 | 当前筛选和关键管理动作 |
| 公告管理 | 发布索引 → 编辑工具栏 → 公告目录 → 正文档案 | 发布时间、投放状态和内容层级 | 创建、发布或停用 |
| 订单 / 支付 | 摘要索引 → 明细行 → 合计 → 状态印记 → 下一步 | 金额、渠道、参考号和结果 | 支付、确认或重试 |

生成时遵守：

1. **先建立可核对的阅读顺序**，再增加边线、编号和材质；视觉装饰不能改变真实业务优先级。
2. **动态集合优先成为连续账簿行**，避免每条记录独立悬浮成 SaaS 卡片；只有需要独立签署、结算或确认的对象才成为凭单。
3. **指标不是装饰性大数字**，必须与后续凭单或登记册存在可解释关系；无真实指标时不保留空壳指标卡。
4. **真实空态仍是一张档案叶**：保留标题、规则线、说明和下一步，但不伪造套餐、会员、订单、余额、计费或安全状态来填充空白。
5. **状态依靠文字、位置和印记共同表达**，不能只靠颜色；平台色仅用于真实平台识别，不接管页面品牌。
6. **工具栏是账簿索引，不是按钮堆**：章节 marker 位于边缘 gutter，筛选器保持完整宽度，移动端按阅读顺序换行。
7. **不可见功能不生成假页面**：受 Feature Flag 控制或当前路由重定向的页面只保留设计意图，待真实功能可达后再做四象限视觉验收。

### 9.3 从“复刻”到“同源生成”的判断

- **复刻正确**：有旧静态基准的页面，结构比例、字体角色、纸面层级、朱砂节制和动效节奏均能对照成立。
- **学习正确**：没有旧静态基准的页面，不复制某张截图，却仍能从业务主语推导出同源的封面、账簿、档案、图版、凭单或附录。
- **延展正确**：新组件继承同一信息语法，但保留 Sub2API 的真实 API、Store、Router、权限、Feature Flag、loading、disabled 和错误状态。
- **结果错误**：只换颜色和背景、机械添加卡片、用假数据制造“丰富感”，或为了视觉一致性删减真实功能。

## 10. 反例

以下做法即使“颜色接近”也不属于 Mexion：

- 纯白或冷灰铺满页面。
- 大圆角、大阴影、玻璃拟态、蓝紫渐变。
- 所有标题、正文、数字都使用同一字体。
- 每张卡片都悬浮并 hover 上跳。
- 红色用于所有按钮、图表和标签。
- 为了像旧静态页而增加后端未启用的入口。
- 在业务组件中复制 API/Store/权限逻辑来配合皮肤。
- 使用 `.card`、`.hero` 等裸选择器污染公共路由。

## 11. 完成标准

每个路由验收至少检查：

- [ ] 与对应旧静态页面的结构、留白、字体角色和材质一致。
- [ ] 新页面能看出来自同一本“技术期刊”，而非另一套 SaaS 模板。
- [ ] 路由、权限、Feature Flag、提交和错误处理仍由 Sub2API 控制。
- [ ] 朱砂使用克制，业务色语义清楚。
- [ ] Dropdown/Popover/Dialog 未被裁剪且层级正确。
- [ ] 桌面、移动端、浅色、暖墨深色可用。
- [ ] 键盘焦点清晰，reduced-motion 下内容立即可见。
- [ ] 页面样式有稳定作用域，没有通用选择器泄漏。
- [ ] `typecheck`、`build`、皮肤契约与视觉审计通过。
